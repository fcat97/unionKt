# unionKt

[![](https://jitpack.io/v/fcat97/unionKt.svg)](https://jitpack.io/#fcat97/unionKt)

Annotation-driven **type unions** (sum types) for Kotlin, generated by KSP.

Declare a marker interface listing the types you want to unify, and unionKt generates a
real `sealed interface` with one case per type plus companion factory functions. Because
the result is an ordinary sealed interface, `when` over it is **exhaustively checked by
the Kotlin compiler** — dropping a branch is a compile error, not a runtime surprise.

```kotlin
@Union(Int::class, String::class, User::class)
private interface ResultSpec

val r: Result = Result.onInt(5)

val out = when (r) {              // remove any branch -> compile error
    is Result.OnInt    -> r.value.toString()
    is Result.OnString -> r.value
    is Result.OnUser   -> r.value.name
}
```

dependencyResolutionManagement {

```kotlin
// build.gradle.kts
plugins {
    kotlin("jvm") version "2.4.20"
    id("com.google.devtools.ksp") version "2.3.12"
}

dependencies {
    implementation("com.github.fcat97.unionKt:annotations:0.1.0")
    ksp("com.github.fcat97.unionKt:processor:0.1.0")
}
```

Replace `0.1.0` with the git tag you want. `annotations` and `processor` are two separate
artifacts under the same group — that is how JitPack exposes the modules of a multi-module
repository (`com.github.<user>.<repo>:<module>:<tag>`).

> These exact coordinates were verified by building a throwaway consumer project against
> the published artifacts, not just asserted.

## The Spec marker convention

**KSP can only generate new code. It can never modify an existing declaration.**

That single constraint shapes the whole API. A processor cannot take your
`sealed interface Result` and add nested cases to it — there is no "edit this file" API,
only `CodeGenerator.createNewFile(...)`. So unionKt inverts the relationship: you annotate
a small **marker** that *names* the union, and the processor owns the generated type
completely.

- You annotate `FooSpec`.
- unionKt generates `Foo` — the marker's name minus the trailing `Spec` — into
  **the same package** (`markerDeclaration.packageName`).

Because the processor owns the whole type, it can nest the cases inside it and attach a
companion object of factories. Annotating a real sealed interface directly could do
neither.

The `Spec` suffix is **mandatory and enforced**. If it is missing, unionKt calls
`logger.error` and skips the marker. It never guesses a name and never silently falls back.

### What gets generated

For the example above, into the marker's package:

```kotlin
internal sealed interface Result {
    public data class OnInt(val value: Int) : Result
    public data class OnString(val value: String) : Result
    public data class OnUser(val value: User) : Result

    public companion object {
        public fun onInt(value: Int): Result = OnInt(value)
        public fun onString(value: String): Result = OnString(value)
        public fun onUser(value: User): Result = OnUser(value)
    }
}
```

Naming rules: member type `T` becomes case `On<T>` and factory `on<T>`, both derived from
`T`'s **simple** name. Cases are `data class`es, so you get `equals`/`hashCode`/`copy` and
destructuring for free.

Code is emitted with [KotlinPoet], not string concatenation, so imports, nullability and
generics are modelled rather than spelled out.

[KotlinPoet]: https://square.github.io/kotlinpoet/

### Visibility

The generated union **mirrors the marker's visibility**, with one deliberate exception:

| Marker            | Generated union              |
| ----------------- | ---------------------------- |
| `interface`       | `public sealed interface`    |
| `internal`        | `internal sealed interface`  |
| `private`         | `internal sealed interface` + warning |

A `private` marker cannot produce a `private` union. The union necessarily lands in its
*own* generated file, and `private` on a top-level declaration means *file*-private — the
union would be invisible to the very file that asked for it. Kotlin has no package-private,
so `internal` is the only level that actually means "don't leak this". unionKt promotes
`private` to `internal` and tells you it did:

```
w: [ksp] ResultSample.kt:11: @Union marker 'ResultSpec' is private; the generated union is
   emitted as 'internal' because a private top-level declaration in the generated file
   would be invisible to 'ResultSample.kt'.
```

If you keep a `private` or `internal` marker, remember that anything exposing the union
must be `internal` too, or Kotlin will reject it for leaking an internal type.

## Exhaustiveness guarantee

This is the point of the library, and it is verified in-tree rather than claimed.

`:sample` applies the KSP plugin with `ksp(project(":processor"))`, so the union is
generated and compiled on every build of this repository. Deleting a branch from the
`when` in `sample/src/main/kotlin/com/github/fcat97/unionkt/sample/ResultSample.kt`:

```kotlin
internal fun describe(result: Result): String = when (result) {
    is Result.OnInt -> "int=${result.value}"
    is Result.OnString -> "string=${result.value}"
    // is Result.OnUser -> ...   <- deleted
}
```

fails `./gradlew build` with:

```
e: ResultSample.kt:18:49 'when' expression must be exhaustive.
   Add the 'is OnUser' branch or an 'else' branch.
```

The check costs nothing at runtime and is enforced by the Kotlin compiler, not by unionKt —
`Result` is a genuine sealed interface with a closed set of implementors.

## Errors

Every precondition fails loudly through `logger.error` and skips the marker. Nothing is
inferred when the input is ambiguous.

| Situation | Message |
| --- | --- |
| Marker is not an interface | `@Union may only be applied to an interface, but 'BadKindSpec' is a class. …` |
| Name does not end in `Spec` | `@Union marker 'BadName' must be named '<Union>Spec' …` |
| Name is exactly `Spec` | same as above (the suffix must be a *suffix*, not the whole name) |
| Two members share a simple name | `@Union on 'ClashSpec' has 2 member types whose simple name is 'User' (…a.User, …b.User), which would generate clashing 'OnUser' cases. …` |
| No member types | `@Union on 'EmptySpec' declares no member types. A union needs at least one.` |
| Marker in the default package | `… must live in a named package …` |
| Marker declares type parameters | `… declares type parameters, which the generated union cannot carry. …` |
| Two markers produce the same union name | `… would generate 'pkg.Foo', which another marker in the same package already generates. …` |

For the simple-name collision case, introduce a wrapper type (or a `typealias` plus a
wrapper) so each member contributes a distinct case name.

## Tests

`:processor-tests` runs the Kotlin compiler in-process with the processor attached, using
[kotlin-compile-testing] (ZacSweers' maintained fork, built against exactly the Kotlin and
KSP versions pinned here).

```bash
./gradlew :processor-tests:test        # or just ./gradlew build
```

This module exists because **failure cases cannot live in `:sample`**. A `logger.error`
fails the build, so the only way to assert that a bad marker produces the *right* message
is to compile it in-memory and read the compiler's output:

```kotlin
@Test
fun `marker without the Spec suffix is rejected`() {
    compileWithUnionProcessor(
        SourceFile.kotlin(
            "BadName.kt",
            """
            package test

            import com.github.fcat97.unionkt.Union

            @Union(Int::class)
            interface BadName
            """.trimIndent(),
        ),
    ).assertFailedWith(
        "@Union marker 'BadName' must be named '<Union>Spec'",
        "Rename it to e.g. 'BadNameSpec'",
    )
}
```

Covered:

- **Every row of the error table above**, asserted on the actual message text — wrong
  declaration kind (class and object), missing `Spec` suffix, a marker named exactly
  `Spec`, the default package, type parameters on the marker, an empty `@Union`, two and
  three members colliding on a simple name, two markers resolving to the same union, and
  an unresolvable member type.
- **Generated shape** — sealed interface, one `data class On<T>` per member, companion
  factories, and emission into the marker's own package.
- **Visibility mirroring** — public stays public, `internal` stays internal, `private`
  becomes internal *and* warns.
- **Exhaustiveness, both directions** — a complete `when` compiles; dropping a branch
  fails with `'when' expression must be exhaustive`.
- **Edge cases** — a generic member star-projects to `List<*>`, a nested member type uses
  its simple name for the case, several markers in one compilation each get their own file.

[kotlin-compile-testing]: https://github.com/ZacSweers/kotlin-compile-testing

## Modules

| Module            | Published | Contents |
| ----------------- | --------- | -------- |
| `:annotations`    | yes    | `@Union(vararg val types: KClass<*>)`, `CLASS` target, `SOURCE` retention. Nothing else. |
| `:processor`      | yes    | `UnionProcessor` + `UnionProcessorProvider`, registered via `META-INF/services`. |
| `:sample`         | **no** | Exercises the generated code in-tree. Not published, no `maven-publish`. |
| `:processor-tests`| **no** | The processor's test suite, run through kotlin-compile-testing. |

`@Union` has `SOURCE` retention: it is a compile-time instruction and leaves nothing in
your class files.

## Compatibility

These pins are what unionKt is *built* with. Consuming projects do not have to match them.

| | Requirement | Notes |
| --- | --- | --- |
| **Kotlin** | 2.3 or newer | `:annotations` carries Kotlin 2.4 metadata; Kotlin reads one minor version ahead, so 2.2 and older reject it. |
| **KSP** | any 2.3.x | The processor uses no API newer than KSP 2.3.0. |
| **AGP** | 9.x needs **KSP 2.3.4+** | Not a unionKt constraint — see below. |

Verified by building a consumer project against the published artifacts for each row:

| Kotlin | KSP | Result |
| --- | --- | --- |
| 2.3.20 | 2.3.0 | pass |
| 2.3.20 | 2.3.2 | pass |
| 2.3.20 | 2.3.6 | pass |
| 2.3.20 | 2.3.12 | pass |
| 2.4.20 | 2.3.12 | pass |
| 2.2.20 | 2.2.20-2.0.4 | **fails** — Kotlin 2.2 cannot read the annotation jar's metadata |

### Android / AGP 9 built-in Kotlin

If your module uses AGP 9's built-in Kotlin (that is, it applies `com.android.library` or
`com.android.application` *without* `org.jetbrains.kotlin.android`), adding **any** KSP
processor on KSP below 2.3.4 fails at configuration time:

```
Using kotlin.sourceSets DSL to add Kotlin sources is not allowed with built-in Kotlin.
Kotlin source set 'debug' contains: [.../build/generated/ksp/debug/kotlin, ...]
```

This is [KSP #2729](https://github.com/google/ksp/issues/2729) — the KSP Gradle plugin
registered its generated directories through `kotlin.sourceSets`, which AGP 9 forbids. It
has nothing to do with unionKt and would happen with Room, Hilt or Moshi just the same.

**Fix: upgrade KSP to 2.3.4 or newer.** Do *not* reach for
`android.disallowKotlinSourceSets=false`; it only silences the check, and Android's own
migration guide advises against it.

## Publishing a release

JitPack builds from a git tag. Nothing else is required — no Sonatype account, no GPG key,
no signing config.

```bash
git tag 0.1.0
git push origin 0.1.0
```

Then either open `https://jitpack.io/#fcat97/unionKt` to trigger and watch the build, or
just depend on the tag — the first resolution triggers the build.

### How the build is wired

[`jitpack.yml`](jitpack.yml):

```yaml
jdk:
  - openjdk17
install:
  - ./gradlew publishToMavenLocal --no-daemon --stacktrace
```

JitPack defaults to JDK 8, which cannot run Gradle 9, so the JDK is pinned. The install
step publishes into the container's `~/.m2/repository`, which is where JitPack harvests
artifacts from.

`maven-publish` is applied to `:annotations` and `:processor` only. Each declares a single
`MavenPublication` from the Java/Kotlin component plus a sources jar.

**Coordinates are never hardcoded.** JitPack does not pass `-Pgroup`/`-Pversion`; it exports
environment variables into the build container:

| Variable   | Value on JitPack     |
| ---------- | -------------------- |
| `GROUP`    | `com.github.fcat97`  |
| `ARTIFACT` | `unionKt`            |
| `VERSION`  | the tag being built  |

The root `build.gradle.kts` joins `GROUP` and `ARTIFACT` into the multi-module group
`com.github.fcat97.unionKt` and takes the version from `VERSION`; each publication then uses
`project.group` / `project.version` with the module name as `artifactId`. Outside JitPack
those fall back to `com.github.fcat97.unionKt` and `0.1.0-SNAPSHOT` so the build stays
publishable locally:

```bash
./gradlew publishToMavenLocal
```
